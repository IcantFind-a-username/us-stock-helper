### 已批准的产品定位

这是一个 iPhone 优先的美股研究、预警、解释和风险计划助手，不是自动
交易机器人。目标是尽可能早、尽可能广地发现全世界可能影响市场和个股
的信息，并把新闻、整体市场情绪、宏观/大盘、地缘政治、机构活动代理、
技术面、财务基本面和顾问观点组合成可追溯判断。

所有事实、关键推断和建议都必须能追溯到来源证据。不能保证盈利、不能把
“潜力翻倍股”说成必然翻倍、不能制造确定性。信息速度最重要，但来源
可靠性、许可、robots、付费墙和供应商条款同样必须遵守，绝不绕过访问
控制。应优先采用官方/监管/交易所/公司披露和合法实时源，并记录发布时间、
首次发现时间、抓取时间、修订和替代关系。

### 三套期限与评分

- 短线：盘中至 5 个交易日，默认展示。
- 波段：1–8 周。
- 中长期：2–24 个月。

三套评分必须有各自的特征、权重、回测、校准、失效条件和建议，不得只把
同一个分数换标签。既有算法是确定性基础；顾问模型只作为有上限、经回测
校准的软因子，与算法互补。

### Dashboard 与主要页面

底部导航固定为：首页、发现、提醒、复盘、Agent。全局保留搜索和通知入口。
Dashboard 默认短线，至少呈现：

- 对整体市场情绪的直观中文结论、当前策略与风险姿态，不只显示数字；
- 新闻/社媒情绪、市场广度、波动率与期权、行业强弱、利率与美元、宏观、
  大盘趋势、流动性、相关性压力和地缘政治等驱动、冲突证据与新鲜度；
- 最高优先级证据预警；
- 从 moomoo 只读同步的关注列表脉冲（未来真实数据阶段）；
- 全市场多头与空头机会、潜力高回报候选股及入选原因；
- 市场时段、数据健康、延迟、缺失和降级状态。

发现页支持长/短候选、期限、催化剂、证据新鲜度、流动性、波动、技术、
机构代理、基本面和风险筛选，明确区分观察池与可行动研究状态。每个排名
显示算法原因、正反证据、引用和失效条件。

提醒页分为信息通知、观察、可行动研究提醒、风险警告。重复或被替代事件
合并为事件链；每条含 ticker、期限、触发条件、时间、来源新鲜度、正反
证据数、基础分贡献、顾问有限调整、失效条件、引用。

复盘页记录用户手动输入或导入的操作、时间、数量、成交价、盈亏、是否遵循
计划、延迟、滑点和笔记。只能用于执行复盘、风险提醒和 UI 偏好，永远不能
成为“股票会上涨/下跌”的证据。

Agent 是安全对话口。回答顺序固定：客观结论 → 证据 → 最强反证 →
缺失信息与不确定性 → 个性化风险场景 → 引用。明确区分事实、推断、场景、
传闻。Agent 可阅读版本化证据包，也可以向信息层提出补充调查请求。

### 个股页与专业 K 线

个股页要显示代码、公司、交易所、价格、涨跌、市场时段、行情延迟、
watchlist 状态和期限。K 线参考 moomoo/同花顺等成熟软件的清晰信息密度和
交互习惯，但不得复制其专有资产、代码或受保护表达。

K 线必须具有：

- 清晰蜡烛实体/影线、右侧价格轴、底部时间轴、成交量；
- 十字光标下的 OHLC、成交量和涨跌；
- 1m、5m、15m、30m、1h、日、周周期；
- 竖屏概览和横屏全屏；
- 主图/副图指标选择、可配置颜色和参数；
- 可点开的事件标记，不能遮住蜡烛；
- 行情来源与延迟状态。

主图可选 MA/EMA、VWAP、布林带、神奇九转、原创“神龙趋势”指标、形态、
支撑阻力和概率预测带。副图可选成交量、MACD、RSI、机构/散户活动估算
代理，以及仅在有可辩护数据源时提供的筹码/持仓分布。

竖屏中 **RSI 和 MACD 必须始终有默认可见的摘要卡，绝不能漏掉**。
RSI 展示值、超买/超卖/中性、趋势、背离、参数、周期；MACD 展示 DIF、
DEA、柱体方向、扩张/收缩、金叉/死叉和周期。

形态提示包括三日分型、头肩顶/底、双顶/W 底、回踩五日线、“回眸一笑”
等文档化原创形态、九转状态、神龙状态、RSI 超买超卖/背离、MACD 多空
与交叉。每个形态必须展示状态、确认度、是否完成、期限和失效条件；未完成
不能冒充已确认。

神奇九转可基于公开通用的 sequential best practice 独立实现；神龙算法
必须自己精心设计、记录公式/版本并做 point-in-time 回测。可以借鉴普遍
最佳实践，但不复制付费产品的专有代码、参数、视觉资产或名称下的受保护
实现。所有指标禁止未来函数和 look-ahead leakage：在时点 t 的输出只能
使用 t 当时可获得且具有可用时间戳的数据，研究/回测/paper/live 使用同一
信号合同。

### “主力”、机构与散户

不要把两个不同概念混在一起：

1. 正式申报的机构/基金/受益人/内部人持仓：注明报告期、申报日期和天然
   延迟，显示进入、退出和变化。
2. 盘中机构型/散户型参与度：只能使用市场微观结构等可辩护特征做
   **估算代理**，显示直方图或占比、方法版本、置信度、覆盖率、时间戳。

不能声称实时知道真实账户身份，不能把 estimated flow 叫作精确机构持仓。
以后发现“主力进场/退场”要由可解释代理、价格/成交量、期权、暗池或合法
数据等交叉验证，并明确误报、滞后和数据缺口。

### 信息、情绪、宏观与地缘政治

未来信息层采用事件驱动：官方推送/webhook/RSS/合规实时源优先，轮询作为
补充；做实体解析、去重、事件链、修订/辟谣、首次发现计时和点时证据快照。
来源优先级：

1. 监管机构、交易所、法院、政府和公司申报；
2. 公司 IR 与官方管理层沟通；
3. 获得许可的行情、期权、做空、持仓数据；
4. 可信新闻与行业来源；
5. 社交/社区只作为低置信线索。

整体市场情绪是确定性基础算法的一部分，必须分析并给出结论和建议，而不是
装饰性新闻卡。大盘可在条款允许时读取 moomoo 数据，但必须有替代数据源。
输入要覆盖指数、广度、行业相对强弱、已实现/隐含波动率及期限结构、利率/
收益率曲线、美元、信用、商品能源、流动性与相关性压力。

地缘政治在消息摄取时就识别，分别标注已确认事实、争议报道、推断暴露和
情景假设；映射区域、公司/子公司、客户供应商、商品、航线、制裁、出口
管制及受影响行业，记录直接性、严重度、方向、置信度、持续时间和引用。
市场/宏观/地缘调整要显示原始个股基础分、环境调整、调整后分数以及因此
改变的入场、仓位、杠杆或提醒条件，不能静默改写事实。

### 基本面

分析财报与公司健康：现金、债务、自由现金流、稀释、资金跑道、利润率、
收入/利润增长、估值、行业与供应链、公司发展前景及重大风险；显示报表期、
发布时间、来源和数据时效。短线也不能完全忽略财务/稀释/事件风险。

### 概率预测

可以预测走势，但禁止画一条看似确定的未来价格线。必须显示期限、中位路径、
50% 和 80% 概率带、上涨/震荡/下跌概率、历史校准误差、预测时间、模型
版本和失效条件。概率需做时间序列 walk-forward、点时数据和校准评估。

### 13 位风格顾问

参考 `virattt/ai-hedge-fund` 作为金融领域顾问思路来源，但不要盲信，不要
默认复制代码，先核验许可证和实现。顾问模块提供以下 13 种“公开理念风格
模拟”：

Damodaran、Benjamin Graham、Bill Ackman、Cathie Wood、Charlie Munger、
Michael Burry、Mohnish Pabrai、Nassim Taleb、Peter Lynch、Phil Fisher、
Rakesh Jhunjhunwala、Stanley Druckenmiller、Warren Buffett。

这些不是本人意见、背书或冒充。顾问先阅读已经由确定性算法形成的证据包，
可以请求信息层补充调查，也可以因证据不足而 abstain。输出结构化论点、
反证、缺口、置信度和引用。它们只是有上限、经回测校准的软因子，影响候选
排序和提醒，绝不能推翻事实、绕过风控或独立触发行动提醒。完整顾问委员会
只用于高价值/疑难/用户明确请求的个股，不扫描每个 ticker 或每个 tick。

### 多空、回报/风险偏好与安全托底

支持基础做多和做空策略。用户可选择保守、均衡、激进或更偏高回报的方案，
但客观基础分、证据可信度、方向概率和模型置信度不能随偏好或用户行为改变。
偏好只能影响风险预算内的方案选择与展示。

每份建议必须包含：方向、入场方式/区间、limit price 建议、数量或仓位、
风险预算、建议杠杆与最大杠杆、失效条件、止损逻辑、目标、reward/risk、
持有窗口和撤销条件。激进方案要显著显示回撤、跳空、流动性、波动、集中度
和本金损失风险，并有硬性仓位/杠杆/数据新鲜度/事件风险托底。

做空计划另外显示借券可用性及时间戳、借券费率、short interest/拥挤度、
squeeze、跳空、停牌、recall 和亏损理论无上限警告。没有新鲜借券信息时
必须降级或不出可执行式计划。

应用 **永远不能自行提交、修改或撤销订单**。只能分析、保存/复制参数或
打开 moomoo 让用户手动输入。不得保存券商交易权限，也不要用任何自动化
绕过该边界。

### moomoo 边界

未来仅在官方接口、用户授权和条款允许范围内，从 moomoo 读取 watchlist
和可用行情/账户只读信息。全网信息不能依赖 moomoo 单一来源。第一版真实
集成也禁止下单；所有建议仍由用户在 moomoo 手工确认执行。

### 审计、自适应学习与客观性

借鉴 Hermes Agent 的版本化审计/学习理念，但只学习市场信息和可验证的
投资经验：使用不可变证据快照、市场经验 memory、离线反思、
champion/challenger、回测门槛、版本、审计日志和一键回滚。不能在线自改
生产策略，不能从用户散户行为学习价格方向。

大模型可记录用户操作、盈亏和偏好，用于复盘、风险提醒、表达层和 UI，
但不得迎合用户、确认偏误或用用户曾经赚钱/亏钱作为市场事实。底层强制
objective factual core：客观结论和最强反证优先，个性化只出现在风险场景。

### LLM Token 效率

以节省 token、提高每 token 信息量为核心：

- 先由确定性流程收集、去重、实体解析、特征计算、筛选和排序；
- 给 LLM 的是紧凑、版本化、带引用 ID 的证据包，不是整页原文；
- 小模型做抽取、分类、去重和普通摘要，困难/高价值/用户请求才升级；
- 按数据快照、ticker、期限、顾问、模型、prompt 版本缓存；
- 批处理相似任务，取消过时请求，只对变化增量分析；
- 记录每次调用 token、费用、延迟、缓存命中、信息增益和对最终决策的贡献；
- LLM 不能凭空造事实，所有结论必须回链到证据 ID。

### Demo 阶段不可越界

在用户确认完整页面组件和交互之前，本阶段只用确定性的本地 fixture 数据：
不接真实新闻、不接 LLM、不接 moomoo、不做登录/云同步、不做订单执行。
每一个金融页面都必须明确显示“演示数据 · 非实时行情”，不能伪装实时。
先完成 UI 和安全/降级状态，再进入后端信息层和真实算法阶段。
