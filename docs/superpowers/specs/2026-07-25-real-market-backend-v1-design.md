# US Stock Helper 真实行情后端 V1 设计

日期：2026-07-25  
状态：待用户书面确认  
目标用户：单用户，新加坡 moomoo 账户  
默认投资周期：短线，盘中至 5 个交易日

## 1. 目标

把已经确认的 iPhone UI 从演示数据切换到可长期运行、可审计、无交易
权限的真实数据闭环。V1 必须让用户在不依赖 Mac 上的 Expo/Metro
开发服务器时，也能打开手机 App 查看：

- 自己的 moomoo watchlist；
- 真实报价和已闭合 K 线；
- 与每根 K 线严格对齐的主力/散户资金代理占比直方图；
- 基于真实 K 线计算的 RSI、MACD、MA5 和九转；
- 明确标注延迟的机构持仓披露；
- 可持久化的交易复盘和个人偏好记忆；
- 每项数据的来源、时点、质量和失效状态。

V1 仍然只提供分析与建议。系统没有下单、改单、撤单或读取交易账户的
能力。

## 2. 已确认的产品边界

### 2.1 第一实现切片

第一切片只负责打通真实市场数据纵向闭环：

1. moomoo watchlist；
2. 报价；
3. 1、5、15、30、60 分钟已闭合 K 线；
4. 逐 K 线资金参与占比；
5. RSI、MACD、MA5、九转；
6. 延迟机构持仓；
7. 手机端真实/延迟/不可用状态；
8. 手工交易复盘、云同步和个人偏好摘要。

日线和周线价格 K 线可以读取，但资金占比只有在 moomoo 官方历史资金
接口通过真实数据验证后才开放。验证前必须显示“不支持”，不得从盘中
数据外推。

V1 分钟资金占比只覆盖 OpenD 资金流实际返回的单个交易日。图表可以显示
更早价格 K 线，但没有同源资金明细的历史 K 线必须显示资金柱缺失，不能
用最近一天、插值或模型估算填充。

### 2.2 后续切片

全球信息优势保留为紧接第一切片的第二切片：

- SEC、公司 IR、交易所、监管机构和政府公告；
- 合规新闻 API/RSS、宏观和地缘政治来源；
- 事件去重聚类、发布时间与事件发生时间分离；
- 市场情绪、行业情绪、个股影响链和主动提醒；
- 每条结论保留 URL、来源、时间、内容哈希和引用；
- 13 位投资顾问只读取证据包，作为有上限的软因子。

网页抓取不能静默替代实时行情或资金分桶。只有授权的行情 API 才能作为
moomoo 的市场数据备用源。

### 2.3 明确不在 V1 范围

- 自动交易或任何券商写操作；
- `OpenSecTradeContext`；
- 交易解锁密码；
- 根据未闭合 K 线生成正式指标、预测或回测结果；
- 将大单代理描述成真实机构身份；
- 将中小单代理描述成真实个人身份；
- 未校准的走势预测；
- 公开销售或重新分发 moomoo 实时行情；
- 多用户账户系统。

## 3. 部署拓扑

### 3.1 云主机

采用 AWS Lightsail 新加坡区域 `ap-southeast-1`：

- Ubuntu LTS；
- 2 vCPU；
- 4 GB 内存；
- 固定公网 IP；
- 自动每日快照；
- HTTPS 域名；
- 单用户部署。

新加坡区域用于保持 OpenD 登录 IP 与用户的新加坡 moomoo 账户地区一致。
用户在中国使用手机时，可以通过新加坡 VPN 访问相同 HTTPS API。手机
所在地不会改变 OpenD 的新加坡固定登录 IP。

### 3.2 网络边界

公网只开放：

- `443/tcp`：手机只读 HTTPS API；
- 受限管理入口：仅允许用户确认的管理 IP 或 AWS 管理通道。

以下服务只监听 `127.0.0.1`：

- OpenD `11111`；
- PostgreSQL；
- 内部 worker 管理端口；
- 指标和抓取内部服务。

不得把 OpenD `11111`、数据库端口或内部调试端口暴露到公网。

### 3.3 移动端身份

App 不显示传统账户登录页。首次安装使用一次性配对码绑定：

1. 云端生成短时有效、单次使用的配对码；
2. iPhone 提交配对码；
3. 云端签发可撤销、可轮换的单设备访问令牌；
4. 令牌只存储在 iOS Keychain；
5. 日常使用无用户名和密码输入；
6. 服务端可以撤销丢失设备的令牌。

即使是单用户，公网 API 也不能处于无认证状态。

### 3.4 独立手机体验

生产测试包直接连接新加坡 HTTPS API，不依赖 Mac 上的 Metro、Expo
开发服务器或家庭局域网。普通 TypeScript UI 开发继续使用 Fast Refresh，
但验收使用独立 Release 构建。

如果已有付费 Apple Developer Program，则使用 TestFlight；否则先用
Xcode 设备签名 Release 包测试，并明确其签名有效期限制。远程推送在
Apple 推送能力可用后单独启用，不阻塞 V1 行情闭环。

## 4. 安全边界

### 4.1 moomoo 只读规则

后端只允许导入和构造 `OpenQuoteContext`。代码库、依赖注入容器和运行
配置中不得出现 `OpenSecTradeContext`。

允许的能力包括：

- `get_global_state`；
- `get_user_security_group`；
- `get_user_security`；
- `get_market_snapshot`；
- `request_history_kline`；
- `get_capital_flow`；
- `get_capital_distribution`；
- `get_shareholders_institutional`；
- 必要的行情订阅和额度查询。

OpenD 登录凭据通过 AWS 加密秘密存储注入。不得提交到 Git、镜像、
日志、崩溃报告或 App。OpenD 配置使用官方支持的加密密码或权限为
`0600` 的运行时秘密文件。系统永不保存交易解锁密码。

### 4.2 应用 API

- 所有公网请求使用 TLS；
- Bearer 令牌不得出现在 URL、查询参数或日志；
- 只暴露允许列表中的 GET/只读查询，以及复盘数据的受控 CRUD；
- 复盘写入与券商交易完全无关；
- API 统一限流、防重放、请求大小限制和结构化审计；
- 错误响应不包含账户 ID、watchlist 全量内容、秘密或原始供应商错误。

## 5. 服务边界

Python 继续作为后端语言，因为 moomoo 官方 SDK、现有分析核心和信息层
均已使用 Python。V1 不引入第二种后端语言。

### 5.1 `market_gateway`

职责：

- 连接本机 OpenD；
- 获取原始市场数据；
- 分类登录、权限、额度和网络错误；
- 将交易所时间转成带时区的 UTC；
- 拒绝未闭合或未来可用数据；
- 不包含技术指标和个人偏好逻辑。

### 5.2 `analysis_core`

职责：

- 把已验证 K 线和资金流聚合到同一时间栅格；
- 计算资金参与占比；
- 计算 RSI、MACD、MA5、九转；
- 输出算法版本、输入截止时间、失效原因和数据覆盖率；
- 不直接访问 OpenD、数据库或大模型。

### 5.3 `cloud_api`

采用 FastAPI 作为公网业务 API：

- 设备配对和令牌轮换；
- watchlist；
- 单股统一快照；
- 复盘 CRUD；
- 个人偏好摘要；
- 数据健康和服务状态；
- 生产缓存与并发请求合并。

### 5.4 `journal_memory`

职责：

- 保存手工交易复盘；
- 计算按策略、周期、方向、杠杆和事件类型划分的统计；
- 生成可审计、可删除的个人偏好摘要；
- 向大模型提供紧凑、相关的检索结果；
- 不修改客观市场特征和客观评分。

### 5.5 第二切片 `information_layer`

现有信息层在后续接入：

- 数据源协调和抓取；
- 事件去重、聚类和证据包；
- 情绪、宏观、行业和地缘因素；
- 只向评分层提供有上限、可回测校准的软因子。

## 6. 统一市场快照

手机端主要读取一个版本化的统一对象：

```text
StockMarketSnapshot
├── schemaVersion
├── symbol
├── interval
├── decisionCutoff
├── sourceStatus
├── quote
├── completedCandles[]
├── participationBars[]
├── indicators
│   ├── ma5
│   ├── rsi
│   ├── macd
│   └── magicNine
├── institutionalHoldings[]
├── provenance[]
└── warnings[]
```

每个子对象必须包含：

- `source`；
- `asOf`；
- `availableAt`；
- `methodVersion`；
- `qualityStatus`；
- 必要的引用或供应商字段说明。

`decisionCutoff` 是该响应允许算法看到数据的统一截止时间。所有输入的
`availableAt` 必须小于或等于它。

建议的只读端点：

- `GET /v1/health`
- `GET /v1/watchlist`
- `GET /v1/stocks/{symbol}/snapshot?interval=5m&count=200`
- `GET /v1/stocks/{symbol}/institutional-holdings`
- `GET /v1/journal`
- `POST /v1/journal`
- `PATCH /v1/journal/{id}`
- `DELETE /v1/journal/{id}`
- `GET /v1/preferences`

复盘端点写入的是用户自己的笔记和交易记录，不是券商订单。

## 7. 资金占比算法

### 7.1 数据含义

moomoo 分钟资金流提供：

- 总净流；
- 超大单净流；
- 大单净流；
- 中单净流；
- 小单净流；
- 分钟时间；
- 数据有效时间。

这些字段是订单规模代理，不是交易者身份。

### 7.2 原始数据校验

对每个原始分钟点检查：

```text
totalNet ≈ superNet + bigNet + midNet + smallNet
```

允许的浮点误差由固定绝对/相对容差定义。真实 NVDA 样本的 391 个分钟点
已验证，最大分桶加总残差约为 `5.96e-8`。生产实现仍需对每次响应重新
校验，不能依赖该样本。

同时检查：

- 时间严格递增；
- 数字有限；
- 不含未来 `availableAt`；
- 数据属于请求证券；
- 分钟序列没有无法解释的倒序或重复；
- 响应完成时间不早于输入可用时间。

### 7.3 分钟差分

资金字段是盘中累计值。对相邻分钟做差：

```text
Δsuper = super[t] - super[t-1]
Δbig   = big[t]   - big[t-1]
Δmid   = mid[t]   - mid[t-1]
Δsmall = small[t] - small[t-1]
```

第一条没有可靠基准时不生成占比。跨交易日不连续差分。

### 7.4 K 线聚合

将分钟差分按美东交易所时间聚合到对应 K 线：

- 只聚合已经闭合的 K 线；
- K 线开闭区间使用左开右闭或等价、固定且测试覆盖的定义；
- 盘前、常规盘和盘后不得意外混合；
- 资金覆盖不完整时返回覆盖率并标记该柱缺失；
- K 线与资金柱必须一一按关闭时间对齐。

### 7.5 占比公式

每根 K 线内：

```text
mainContribution =
    Σ|Δsuper| + Σ|Δbig|

retailContribution =
    Σ|Δmid| + Σ|Δsmall|

denominator = mainContribution + retailContribution

mainShare = mainContribution / denominator
retailShare = retailContribution / denominator
```

约束：

- `mainShare + retailShare = 1`；
- 两个占比都在 `[0, 1]`；
- `denominator` 为零或低于噪声阈值时返回缺失；
- 保存主力、散户和总净流美元值用于审计，但 V1 图表不显示正负轴；
- 输出 `methodVersion = "order-size-activity-share-v1"`。

### 7.6 手机图表

已确认的表现形式：

- 每根已闭合 K 线正下方一根等高 100% 直方柱；
- 深色段为主力代理；
- 浅色段为散户代理；
- 不显示零轴；
- 不把资金方向编码进柱子；
- 点击或长按显示精确占比、覆盖率、来源和时间；
- 校验失败时该根柱显示缺失，不插值、不补随机值；
- 文案使用“主力代理/散户代理”或“订单规模活动占比”，不写“真实机构
  持仓占比”。

## 8. 技术指标

所有指标只读取按时间排序的已闭合 K 线。

### 8.1 MA5

- 使用最近 5 根收盘价简单移动平均；
- 不足 5 根时返回不可用；
- 结果的 `availableAt` 等于第 5 根输入 K 线关闭后可用时间。

### 8.2 RSI

- Wilder RSI；
- 默认周期 14；
- 不足热身数据时返回不可用；
- 状态阈值：超买、接近超买、中性、接近超卖、超卖；
- 背离只在独立、经测试的形态逻辑确认后输出。

### 8.3 MACD

- EMA 12 / EMA 26；
- Signal EMA 9；
- 输出 DIF、DEA、柱值、金叉/死叉和扩张/收缩状态；
- 热身区间不得冒充稳定值。

### 8.4 九转

V1 使用原创、公开可解释的九转实现：

- 当前收盘价与 4 根之前收盘价比较；
- 连续满足上涨或下跌条件时计数；
- 条件中断立即重置；
- 最多显示 9；
- 只使用当前及更早 K 线；
- 输出方向、当前计数、是否完成、失效原因和算法版本。

九转是技术特征，不直接等于买卖信号。

## 9. 机构披露

`get_shareholders_institutional` 数据必须标记为延迟披露：

- 报告期；
- 报告期结束时间；
- 实际可用时间；
- 机构数量和变化；
- 持有股数和比例；
- 来源；
- `reportedAtBasis = reporting-period-end`。

机构披露不得与盘中大单代理合并成“实时机构买卖”结论。

## 10. 复盘与个人记忆

### 10.1 手工复盘字段

- 证券；
- 做多/做空；
- 计划周期；
- 开仓和退出时间；
- 开仓、退出和止损价格；
- 数量、名义仓位和杠杆；
- 手续费；
- 入场理由；
- 失效条件；
- 关联策略和证据；
- 实际盈亏；
- 最大有利/不利变动；
- 执行偏差；
- 自评和复盘结论。

复盘数据库、磁盘和备份必须加密。日志不得记录完整复盘正文，数据库备份
需要经过定期恢复演练。

### 10.2 两类记忆严格分离

客观市场记忆：

- 只学习市场数据、信号表现、预测校准和事件结果；
- 不读取用户偏好来修改事实或客观评分。

个人复盘记忆：

- 总结周期、风险、方向、策略和执行偏好；
- 识别追高、过度交易、扛亏、提前止盈等行为模式；
- 只影响“个人适配建议”和风险提示；
- 不能提高股票客观评分；
- 不能隐藏反证；
- 不能为了迎合用户改变事实结论。

### 10.3 Token 效率

大模型不重复读取全部复盘历史。后端预先计算：

- 按策略和周期聚合的统计；
- 最近相关交易；
- 稳定偏好；
- 反复出现的错误；
- 与当前证券/形态最相关的少量记录。

每次调用只发送紧凑证据包和相关记忆摘要。用户可以查看、纠正、导出或
删除个人记忆。

## 11. 数据状态与降级

统一状态：

- `live`：当前请求得到的已验证真实数据；
- `delayed`：供应商明确延迟的数据；
- `stale`：最后已验证数据超过允许新鲜度；
- `unavailable`：权限、网络、额度、校验或覆盖失败；
- `demo`：仅在显式演示模式中使用。

规则：

- 生产模式不得把 fixture 静默混入真实快照；
- 断网时可以显示最后一次已验证缓存，但必须显示原始时间和 `stale`；
- 不允许缓存数据重新标记为 `live`；
- OpenD 离线、需要登录、权限不足和额度不足分别报告；
- 手机通过新加坡 VPN 连接失败时使用指数退避重试；
- 服务恢复后重新拉取完整快照，不拼接未知时间段；
- 任何失败都不得导致自动交易，因为系统没有交易能力。

## 12. 运行监控

- OpenD 进程健康、登录状态和行情权限；
- API 进程和数据库；
- 请求延迟和错误率；
- moomoo 频率与订阅额度；
- K 线缺口；
- 资金分桶校验失败；
- 数据新鲜度；
- 磁盘、内存和 CPU；
- 抓取任务积压；
- 备份成功和恢复演练。

OpenD 或 API 进程自动重启。需要人工重新登录时，通过安全管理通知提示，
不在普通错误响应中暴露账户信息。

## 13. 测试策略

### 13.1 单元测试

- 时间解析和美东交易时段；
- 未来数据拒绝；
- K 线闭合；
- 分桶加总；
- 分钟差分；
- K 线资金聚合；
- 100% 占比不变量；
- MA5、RSI、MACD、九转已知向量；
- 复盘统计和记忆边界；
- API 输入和错误清洗。

### 13.2 性质测试

- 所有占比有限并位于 `[0, 1]`；
- 有效柱的占比和为 1；
- 添加未来行不能改变历史时点输出；
- 重新排序、重复或缺失数据会被拒绝或显式降级；
- 任何用户偏好不能改变同一证据包的客观市场评分。

### 13.3 真实数据重放

保存脱敏、不可反推出账户的 moomoo 响应快照：

- 正常交易日；
- 盘前、常规盘、盘后；
- 低成交量；
- 数据缺口；
- 权限不足；
- OpenD 时钟偏差；
- OTC 或不支持证券；
- 机构披露分页。

重放测试必须离线、可重复，且不能包含登录凭据或完整私人 watchlist。

### 13.4 云端集成测试

- 新加坡 OpenD 登录和 LV3 权限；
- watchlist；
- 报价；

- K 线与资金柱一一对齐；
- 深浅段合计 100%；

- 机构持仓显示延迟说明；
- 网络断开、恢复和 OpenD 离线不崩溃；
- 复盘新增、编辑、删除和重新打开后仍存在；
- 所有真实结论可追溯到来源和时点。

## 14. V1 完成定义

V1 只有同时满足以下条件才算完成：

1. AWS Lightsail 新加坡实例 24 小时运行；
2. OpenD 使用用户的新加坡 moomoo 账户登录；
3. 云端只读边界通过检查；
4. iPhone Release 构建可以独立启动；
5. 手机显示真实 watchlist 和报价；
6. 手机显示真实已闭合 K 线；
7. 每根支持的 K 线下方显示经过校验的纯 100% 资金占比柱；
8. RSI、MACD、MA5、九转来自真实闭合数据；
9. 机构数据明确标注延迟；
10. 复盘和个人记忆云同步可用；
11. 断网、VPN 中断、OpenD 离线和权限异常都有明确状态；
12. 自动化测试、静态检查和真实数据冒烟测试全部通过；
13. 不存在交易上下文、下单路由或交易解锁秘密；
14. 代码、部署配置和运行手册推送到指定 GitHub 仓库。

## 15. 后续顺序

V1 验收后按顺序继续：

1. 全球一手信息源和证据存储；
2. 新闻聚类、宏观、行业、地缘与市场情绪；
3. 异动和事件主动提醒；
4. 可回测的短线/波段/中长期评分；
5. 校准预测；
6. 13 位顾问证据包咨询；
7. 有上限的个人适配建议；
8. 多用户隔离和朋友测试。

该顺序不降低全网信息的重要性，而是先建立可靠的市场数据与时序地基，
避免消息、算法和大模型建立在演示或错位行情上。
