US Stock Helper · Architecture v1

证据先行，算法打底，顾问校准

先用全网信息与确定性算法缩小范围，再让大模型只阅读高密度证据包。 顾问不能凭空制造行动提醒，也不能直接控制仓位或交易。

系统最高原则 信息层是事实来源；算法层给出基础分；顾问层是有上限、经回测校准的软因子。所有结论可追溯、可复现、可质疑。
01

关注范围

  • moomoo 仅读取 Watchlist / 持仓标的
  • 另有全市场候选发现器
  • 每个标的绑定三个独立周期
02

信息获取层

  • 监管、交易所、公司 IR、财报与公告
  • 实时行情、期权、做空与机构披露
  • 新闻、行业源、社媒仅作线索入口
  • 检测异动后主动补充调查
03

证据引擎

  • 去重、实体对齐、可信度与冲突检测
  • first-seen 时间与 point-in-time 快照
  • 事实、推断、传闻严格分层
  • 每条事实都有 source ID 与原文引用
04

确定性算法层

  • 事件冲击、资金代理、技术面与基本面
  • 候选股发现与异常模式扫描
  • 神奇九转、自研神龙等无未来函数指标
  • 先输出可复算的基础分
短线盘中–5日
波段1–8周
中长线2–24月
05

证据门控的 Agent 顾问层

  • 只读版本化“紧凑证据包”，不把整篇网页和行情流水塞进上下文
  • 按周期选择顾问；高分候选、重大分歧或用户深度咨询才触发辩论
  • 可向信息层发结构化补查请求，等待新证据包后再判断
  • 输出论点、反证、引用、缺失证据、置信度、弃权状态与 Token 成本
06

校准与融合

  • 样本外表现决定顾问权重，失效可降至 0
  • 市场状态感知，顾问与周期各自设上限
  • 算法与顾问互补，但不允许顾问越过证据门槛
  • 冲突不被抹平，直接展示给用户
07

排序、提醒与 iOS

  • Dashboard 默认短线，周期一键切换
  • 提醒附触发原因、失效条件与原始引用
  • 观察池、行动提醒、风险警报分级
  • 只提供决策辅助，MVP 不自动下单
08

审计与学习闭环

  • 保存快照哈希、提示词/模型版本、引用、Token 花费和最终结果
  • 同一条管线贯穿回测、模拟盘和实盘观察，避免研究/线上口径漂移
  • 评估“提醒是否及时且有用”，而不仅是模型文案看起来是否聪明

Token 效率路由

大模型是一种昂贵推理资源，不是数据管道。每次调用都要有明确的信息增益。

1
程序先过滤采集、去重、计算指标、排序、规则判断均不调用 LLM。
2
证据压缩只发送结构化事实、关键数字、短摘录和引用指针。
3
小模型先行分类、抽取、去重用便宜模型；复杂冲突才升级强模型。
4
缓存与批处理按快照哈希＋顾问＋版本复用结果，合并相似任务，取消过时工作。
5
有限辩论不让所有顾问扫描所有股票；只为高价值候选启用。
核心运营指标：缓存命中率、每条有效提醒 Token、每 1k Token 的预期信息增益、调用后排序变化、提醒收益/误报率。

算法优先的非对称融合规则

算法强＋顾问同意在软因子上限内提高排名与提醒等级。
算法强＋顾问反对保留提醒，展示冲突并降低置信度。
算法弱＋顾问强只进入观察池或触发补查，不发行动提醒。
证据不足禁止升级；顾问应弃权而不是补全故事。
🛡️ 任一 LLM 都不能单独制造“立即买入”类行动提醒，也不能直接决定仓位或执行交易。
