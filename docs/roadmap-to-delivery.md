# 交付路线图：从当前代码库到可日常使用的原生 iOS App

最终目标：一个能脱离 Mac 独立运行的原生 iPhone App，覆盖产品愿景十三章的全部能力，用于辅助美股投资决策。本文件记录 2026-08-12 由多智能体评审（9 个子系统读取 + 5 项原则对抗核查 + 完整性评审）得出的现状判断与开发顺序，是后续每个迭代的依据。

## 一、现状：什么已经真的成立

对抗性核查对四条不可妥协原则给出结论：

| 原则 | 结论 | 依据 |
|---|---|---|
| 只读行情、绝不触碰交易接口 | 成立 | `services/` 全目录对 `TradeContext`/`place_order`/`unlock_trade` 等零命中；适配器唯一上下文是 `OpenQuoteContext`；冒烟脚本还会递归扫描响应拒绝交易能力标识 |
| 主力/散户占比是代理信号、不冒充机构持仓 | 成立 | 数据契约、网关、图表几何、UI 四层均有防线；不足之处是算法版本串未在任何界面展示 |
| 预测输出概率分布、带反方证据与失效条件、永不自动下单 | 成立（库级） | 预测恒为三情景 + 概率，无单点目标价；硬风控门可将仓位与杠杆归零；顾问调整封顶 ±3 |
| 严禁未来函数、不静默吞掉违规时序 | **部分成立** | 分析核心与解码器严格；但网关把 K 线 `available_at` 写成理论收盘时刻而非真实接收时刻，且多处对越界数据静默降级 |

## 二、现状：与愿景的真实差距

代码库当前是「一条真实行情竖切片 + 一套高质量分析库 + 一个演示态 App」。愿景中以下能力**零实现或未接线**：

1. 期权异动、社媒情绪、全市场扫描（愿景 1/8）——无数据源，无 screener。
2. 事件级情绪打分器（愿景 4）——聚合链路完整，但真实 feed 的 sentiment 恒为 0。
3. 13 位顾问的真实调用与补充调查闭环（愿景 10）——**已部分入账**（2026-08-15 更正：`adviser_llm` 以官方 SDK 真实调用 Claude，落地检查带 FabricatedFactError、实测成本 $0.0993/次，news 路径已从手机一键可达；顾问调整已并入服务分数的单一口径）。仍缺：补充调查受理端、共识/分歧结构、13 席全会诊的手机端渲染（排入 demo-parity 计划）。
4. 审计复盘与自适应学习（愿景 11）——无 outcome 回填，无 walk-forward/Brier 校准，`CalibrationStatus` 只能永远是 UNCALIBRATED。
5. 云端常驻部署（愿景 12）——无 `cloud_api`，iOS 仍依赖 Mac + 局域网。
6. 专业 K 线交互（愿景 6）——**已部分入账**（2026-08-15 更正：捏合缩放（焦点锚定）、平移（活边重锚定 + 时间戳重锚定）、点按/长按读数已实现于 PriceChart）。仍缺：十字光标拖拽、水平价格线、横屏、绘图工具、复权切换（仍硬编码前复权 QFQ）、VWAP/MA10/MA20 叠加。
7. 背离检测（愿景 7）——移动端有 UI 契约，服务端无引擎。
8. 波动率估计器——`forecasting` 要求调用方注入年化波动率，全仓库无实现，这是真实模式下预测恒为 null 的根因之一。
9. **决策链服务化接口**——`decision_engine`/`adviser_layer`/`information_layer` 都是纯库，没有 API 层，评分、预测、顾问结论在真实模式下没有任何通道到达手机。这是愿景 2/8/9/10 在真实模式集体落空的共同缺口。

## 三、必须先解决的跨层矛盾

1. **PIT 链条跨层不自洽**：分析层的点时保证建立在 `available_at` 可信之上，而网关把 K 线 `available_at` 写成理论收盘时刻；更严重的是 K 线硬编码前复权，除权除息会回溯改写全部历史价格——每次拉取的"历史"并非点时不可变。
2. **fail-closed 双标**：同一类时序违规在报价路径抛错、在 K 线路径静默跳过，`snapshot.py` 还会把时序违规错报为"数据缺失"。
3. **双指标引擎分裂**：主仓未提交的 `src/us_stock_helper`（神奇九转 + 神龙指标）与 worktree 的 `analysis_core` 各有一套九转，规则相同但语义不一致，且新代码没有算法版本字段——在可追溯性上相对旧实现是倒退。
4. **顾问封顶口径分裂**：`council.py` 默认 4.0、engine 传 3.0、移动端按 ±10 展示，无共享常量。
5. **文档漂移**：交接文档停在"Task 5"而实际已完成 11 项；README 声称路径白名单 7 条实为 8 条；README 的测试命令照做必报 `ModuleNotFoundError`。

## 四点五、第一轮客观评审的结果（2026-08-12）

对 `8a61cc9..HEAD` 的全部改动跑了 7 个独立评审代理 + 每条发现两名对抗性验证者。评审在我自己刚写的代码里找出了真实缺陷，全部已修并有测试固化：

| 缺陷 | 性质 |
|---|---|
| `except PointInTimeViolation` 是死代码，批次级未来数据仍被吞 | 我引入的守卫从未生效 |
| 非 ASCII `Authorization` 头令处理线程崩溃并打印含路径堆栈 | 认证前的安全缺陷 |
| 神龙指标把首个可测量 K 线报成"趋势转换" | 信号位置随取数窗口漂移 |
| `perfected` 在未检查时发布 `False` | 把"没检查"当成"检查过且不完美" |
| 量能确认测试两个分支产出完全相同 | 空转测试，已用变异验证修复后有效 |
| 无 K 线时发 `priceAdjustment: "unknown"` | 合法快照被 App 整份拒绝，空态不可达 |
| `received_at` 缺失时回退为最早值 | 恰好使截止校验失效 |
| 契约加必填字段却无版本信号 | 旧网关被报成"数据损坏"而非"版本过旧" |
| 四个屏幕在真实模式渲染演示分析 | 违反最重要的红线 |
| 顾问封顶三处口径不一（3 / 4 / 10） | App 把顾问权重夸大三倍以上 |

评审共提出 40 条，其中 **29 条经对抗性验证被证伪**，11 条确认为真并全部修复。其中三条值得单独记：

## 四点六、第二轮客观评审（阶段 6，2026-08-12）

5 个维度评审员 + 每条发现两名对抗性验证者，提出 34 条，**15 条被证伪**、19 条确认。最重要的三条都是我自己新写的代码：

- **`denies` 把否认欺诈翻成最看多分数**（critical）。"Wirecard denies fraud allegations" 得 +0.9——词典能给出的最高分之一。一条欺诈新闻读成当天最好的消息。修法要有金融常识而非逻辑取反：否定正面说法是负面，否定负面说法只向中性衰减。
- **Form 4 归属把内幕交易挂到错误的股票上**（critical）。伯克希尔作为 DaVita 的内部人申报 Form 4，两者都上市，于是"第一个能查到 ticker 的候选"把 DaVita 的内幕交易记到了伯克希尔自己的股票下——relevance 1.0、已核实、可信度 0.99，这个系统能产出的最可信形态，而且完全错误。我在 docstring 里断言"内部人的 CIK 绝不在登记表中"，但企业型 10% 股东既是内部人也是发行人。评审还证明我用归档路径找发行人的补救**在 499 条实况数据里一次都没生效**。EDGAR 的标题里本来就写着 `(Issuer)`/`(Reporting)`，那才是答案。
- **未测量状态在簇层与 packet 层丢失**（critical）。事件层做的排除被上面两层抵消：全部读不懂的簇仍以满权重投 0.0 票，行动分被腰斩；全盲 packet 输出自信的"中性"且无任何提示。

一个额外教训：修 FDA 拒批时我顺手加了"虚词不消耗否定窗口"的特例，变异测试显示它**从未被行使**——窗口值本身就够。未被行使的特例已删除，而不是留着当装饰。

## 四点七、第三轮客观评审与修复（`1cadc7e..310e581` 38 提交 + 阶段 5 核心 5439941/0961e05，2026-08-15）

8 个风险维度评审员 + 每条 critical/important 两名、minor 一名对抗性验证者，提出 25 条，**1 条被证伪**、24 条确认（critical 2 / important 11 / minor 11），全部核实存在于当时 HEAD。两条 critical 落在同一红线类——**"系统越盲、越显得自信"**：

- **截止时间在取证据之前采样**（critical，修复 `258f37b`）。`as_of` 在拉取 K 线后、拉取证据前定格，于是本次请求首次抓回的每条新闻都带着 `available_at > as_of` 被 packet 构建器静默排除——恰好是"用户看到新闻才来查"的那次请求必然看不到该新闻。响应照常以 `live` 状态发出：中性情绪、满因子权重、零引用、零披露。注释里"数据到手后再取截止"的修法只用在了 K 线侧；`excluded_future_event_ids` 被构建器如实报出，然后没有任何人读它。现在截止在全部取数之后采样，残余排除（禁运/时钟偏差）进 notes 披露。
- **market_sentiment 永远不可能报"不可用"**（critical，修复 `ea91278`）。5439941 加的 None 通道对这个因子不可达：`action_score` 是裸 float，零新闻和"读不懂"两种情况都产出测得的 0.0。pattern 因子同病：窗口短于一切检测器最小样本时仍报"测得 0"，使 `available_weight==0` 的 never-actionable 门在生产路径上是死代码。现在"没测"与"测得中性"在类型上分离（`action_score_measured` 必填布尔），空窗因子被诚实重归一化。

第二个反复出现的类是**装配缺口让修好的机器成为死代码**：生产装配不传 CIK 登记表，上一轮修好的 Form 4 归属机器在生产里一次都不会运行（修复 `29e1fbe`：无登记表拒绝构造 SEC 适配器）；`reportRevoked`/`forgetDevice` 无任何产品代码调用，服务端吊销后 App 永久卡死（修复 `afef2e3`+`f6946ef`）；`evaluate` 的顾问通道从未收到 opinions，顶层 `adviserAdjustment` 恒为假 0.0（修复 `b05de28`+`0495488`：null-or-折算的单一口径契约）。三处共同点：**函数被测试调用过，掩盖了没有人接线的事实**。

其余确认项与修复：共享可变 gaps 列表跨请求竞态（`e4ad724` 请求域化 + `8b5ebe2` collector/coordinator 加锁与原子预约）；落地检查只盖 conclusion.statement，五个自由文本字段可携带幻觉直达手机（`8390099` 全字段过检）；200 天新鲜度阈值使按期年报公司每年春天被断言"停止申报"、53 周财年同比失真（`7f091d7`）；日 K 配 20 分钟预算使短线永远 stale_data（`20c7260` 按数据周期定预算）；榜单把被硬门拦截的分数渲染成干净分数（`3f32af7`）；图表 56pt 硬常量致触点偏移（`d2ebda0`）、平移窗口在序列身份/滚动变化时静默换片段（`cb4325b`+`eb64f23` 时间戳重锚定）；配对活码被死行挤出候选窗（`b0829fd`）、坏 Keychain 烧一次性码（`c30be17`）；preflight 在 pipefail 下中途吞检查、防火墙误报非 22 端口 SSH（`b51c5ac`）；smoke 吞 phone-gateway 检查、报告写失败抢占 blame（`d7787b1`）；顾问封顶默认值残留（`8693bb3`）；riskPlan 解码静默强转（`2e35e92`）。

修复分两轮：轮 1 十一单元并行落地后，两名分险复审员（PIT/金融语义/并发簇 + 机械簇）在修复本身里再抓出 3 条 important（collector 锁只修一半、恢复入口悬浮在 tab 栏上会误触烧凭证、图表重锚定只修了换标的场景）与 3 条 minor，轮 2 全部收口。期间还发现并修复了**根布局缺失 SafeAreaProvider（生产启动即崩的潜伏缺陷）**。终态：10 个 Python/deploy 套件 + 移动端 829 测试 + typecheck 全绿。

唯一被证伪的一条值得记录：useAdviserDecision 的跨 scope 状态保留——验证者确认代码机制描述完全准确，但失败场景在现有导航结构下不可达。**机制正确不等于缺陷成立，可达性是发现的一部分。**

教训追加进流程：

- **截止时间必须在全部取数完成后采样**；任何"部分数据在截止后到达"的排除都必须出现在披露里——排除计数已经算出来却没人消费，是新的一类死守卫。
- **类型上不可为 None 的字段就不可能诚实降级**。给因子加"不可用"通道时，要证明生产路径真的能产出 None，否则通道是装饰。
- **每条修复要验证到装配层**：函数被测试调用不算被产品调用；关键依赖（登记表、吊销回路、顾问通道、SafeAreaProvider）应让缺失装配大声失败。
- **一条发现的每个半场都要修完才算关闭**：锁只锁一半、重锚定只覆盖换标的场景，都会在复审里被重新打开。
- **fixture 不得使用线上不可能出现的形状**（`available_at == as_of` 的 K 线、已在几何坐标系里的触点）——这类 fixture 让整个缺陷类对测试免疫。
- **落地/封顶这类不变量要对全部输出字段成立**，只检查一个字段的守卫等于给注入者画出免检通道。
- **评审员被预告"发现将被对抗性验证"后自我过滤显著增强**（本轮 25 提 1 伪，此前两轮为 40 提 29 伪、34 提 15 伪）——此预告写入评审派发模板。

## 五、贯穿始终的红线

来自产品设计的十条不可妥协原则在每个阶段都适用，其中最容易被工程便利侵蚀的三条需要在每次评审时专门核对：

- 真实数据、代理数据、模型推断、演示数据必须显式区分；没有可靠数据时显示"不可用"，不得用装饰性假数据填充。
- 任何数据都按真实 `available_at` 截止；违规时序数据不得被静默修补或部分吞掉。
- 顾问只提供有上限的软因子，不能代替证据层与风控层。
