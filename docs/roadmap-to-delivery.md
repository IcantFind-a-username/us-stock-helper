# 交付路线图：从当前代码库到可日常使用的原生 iOS App

最终目标：一个能脱离 Mac 独立运行的原生 iPhone App，覆盖产品愿景十三章的全部能力，用于辅助美股投资决策。本文件记录 2026-08-12 由多智能体评审（9 个子系统读取 + 5 项原则对抗核查 + 完整性评审）得出的现状判断与开发顺序，是后续每个迭代的依据。

## 一、现状：什么已经真的成立

对抗性核查对四条不可妥协原则给出结论：

| 原则 | 结论 | 依据 |
|---|---|---|
| 只读行情、绝不触碰交易接口 | 成立 | `services/` 全目录对 `TradeContext`/`place_order`/`unlock_trade` 等零命中；适配器唯一上下文是 `OpenQuoteContext`；冒烟脚本还会递归扫描响应拒绝交易能力标识 |
| 主力/散户占比是代理信号、不冒充机构持仓 | 成立 | 数据契约、网关、图表几何、UI 四层均有防线；不足之处是算法版本串未在任何界面展示 |
| 预测输出概率分布、带反方证据与失效条件、永不自动下单 | 成立（库级） | 预测恒为三情景 + 概率，无单点目标价；硬风控门可将仓位与杠杆归零；顾问调整封顶 ±3 |
| 严禁未来函数、不静默吞掉违规时序 | **部分成立** | 分析核心与解码器严格；但网关把 K 线 `available_at` 写成理论收盘时刻而非真实接收时刻，且多处对越界数据静默降级 |

## 二、现状：与愿景的真实差距

代码库当前是「一条真实行情竖切片 + 一套高质量分析库 + 一个演示态 App」。愿景中以下能力**零实现或未接线**：

1. 期权异动、社媒情绪、全市场扫描（愿景 1/8）——无数据源，无 screener。
2. 事件级情绪打分器（愿景 4）——聚合链路完整，但真实 feed 的 sentiment 恒为 0。
3. 13 位顾问的真实调用与补充调查闭环（愿景 10）——顾问目前只是元数据标签，`select_advisers`/`build_compact_packet` 无消费者。
4. 审计复盘与自适应学习（愿景 11）——无 outcome 回填，无 walk-forward/Brier 校准，`CalibrationStatus` 只能永远是 UNCALIBRATED。
5. 云端常驻部署（愿景 12）——无 `cloud_api`，iOS 仍依赖 Mac + 局域网。
6. 专业 K 线交互（愿景 6）——捏合缩放、平移、十字光标拖拽、横屏、绘图工具、复权切换全部缺失；复权硬编码前复权 QFQ。
7. 背离检测（愿景 7）——移动端有 UI 契约，服务端无引擎。
8. 波动率估计器——`forecasting` 要求调用方注入年化波动率，全仓库无实现，这是真实模式下预测恒为 null 的根因之一。
9. **决策链服务化接口**——`decision_engine`/`adviser_layer`/`information_layer` 都是纯库，没有 API 层，评分、预测、顾问结论在真实模式下没有任何通道到达手机。这是愿景 2/8/9/10 在真实模式集体落空的共同缺口。

## 三、必须先解决的跨层矛盾

1. **PIT 链条跨层不自洽**：分析层的点时保证建立在 `available_at` 可信之上，而网关把 K 线 `available_at` 写成理论收盘时刻；更严重的是 K 线硬编码前复权，除权除息会回溯改写全部历史价格——每次拉取的"历史"并非点时不可变。
2. **fail-closed 双标**：同一类时序违规在报价路径抛错、在 K 线路径静默跳过，`snapshot.py` 还会把时序违规错报为"数据缺失"。
3. **双指标引擎分裂**：主仓未提交的 `src/us_stock_helper`（神奇九转 + 神龙指标）与 worktree 的 `analysis_core` 各有一套九转，规则相同但语义不一致，且新代码没有算法版本字段——在可追溯性上相对旧实现是倒退。
4. **顾问封顶口径分裂**：`council.py` 默认 4.0、engine 传 3.0、移动端按 ±10 展示，无共享常量。
5. **文档漂移**：交接文档停在"Task 5"而实际已完成 11 项；README 声称路径白名单 7 条实为 8 条；README 的测试命令照做必报 `ModuleNotFoundError`。

## 四、开发顺序

每一阶段都以 TDD 推进：先写会失败的测试固化契约，再实现到全绿，再交由独立评审代理对抗性复核。

- [x] **阶段 1 · 收敛红灯契约**（2026-08-12 完成，commit `2c5ba62`）
      三层共 27 个失败测试编码的是同一套收紧契约：参与度必须精确完整覆盖且份额由活动量推导、供应商时间戳零容忍未来、资金流要求会话元数据与标的一致、快照错误码保真、LAN token 提升到 32 字符并拒绝过宽 CIDR、客户端不再自算 MA5、真实模式隐藏演示分析面。
- [x] **阶段 2 · 收敛双指标引擎**（commit `908512b`）
      `analysis_core` 为 canonical。九转合并为 `patterns.td_setup`（`td-setup-close-4-v2`），逐根计数 + 完成信号 + bar 8/9 完美化；`magic_nine` 改为描述当前进行中的序列而非历史上第一个，完成过的九转由快照与个股页并列展示，不会在下一根就消失。神龙指标以 `trend.dragon_trend`（`dragon-trend-ema-atr-volume-v1`）落地，指数均线带 warm-up、ATR 归零时报"不可用"而非除以零。
- [x] **阶段 3 · 偿还 PIT 语义债**（commit `ed8ee6c`）
      K 线现在同时携带 `availableAt`（交易所发布时刻）与 `receivedAt`（网关真实持有时刻）；快照与每根 K 线声明 `priceAdjustment`，前复权会在 warnings 中明确披露"除权除息会回溯改写历史序列"，并显示在个股页；新增 `PointInTimeViolation` 把"越过决策截止的未来数据"与"结构性损坏"分开——前者使整个快照失败，后者才允许降级为"不可用"。
- [ ] **阶段 4 · 打通并证明真实端到端**
      跑通 OpenD 登录与 live 冒烟；修复文档漂移；建立 workspace 级包安装机制以消除拼 `PYTHONPATH` 的脆弱态；为快照请求加连接复用与节流。
- [ ] **阶段 5 · 决策链服务化（枢纽）** — 进行中
      - [x] 波动率估计器（commit `6943a23`）：`volatility.estimate_annualized_volatility`，按 K 线周期年化，平盘与样本不足都报"不可用"而非默认值；已接入快照与个股页。
      - [ ] 把评分、三情景预测、决策引擎输出封装为 HTTP API 供移动端消费。**注意**：评分需要消息面、宏观、地缘、机构资金四个因子，目前真实链路只有行情。在信息层（阶段 6）产出真实因子之前，不得用 0 填充这些因子——那会把"数据缺失"伪装成"中性判断"，直接违反红线。因此阶段 5 的评分与预测部分应等待或与阶段 6 并行。
- [ ] **阶段 6 · 信息层生产化** — 进行中
      - [x] **事件级情绪打分器**（commit `a6ab3e4`、`f1f69a9`）：确定性金融词典 + 否定处理 + 短语优先 + 按量级加权。不调用大模型，因为输出会变的打分器无法回测或审计。**关键设计**：读不懂的文本报"未测量"而非"中性"——旧实现让每条真实事件都以 0.0 出生，聚合层无法区分"没读"与"读了是中性"。聚合时未测量事件不参与情绪加权，但仍计入独立来源数。
      - [x] **CIK→ticker 归属**（commit `270bbbf`、`9284f2d`）：申报按申报人身份归属而非正文措辞。**关键修正**：EDGAR 用申报人给 Form 4 命名，取标题 CIK 会把内幕交易归给自然人（无股票代码），信号被静默丢弃；现在收集条目中所有 CIK 交由登记表消歧——自然人 CIK 不在表内，发行人自然浮现。
      - [x] **语义级跨源同事件聚类**（commit `f5daa0c`、`3cb0593`）：旧实现按 claim_key/content_hash 精确匹配，两家媒体报道同一事件因 URL 与措辞不同永远分属两簇，"≥2 独立来源"这道门槛在真实新闻流里从未打开过。改为保守规则合并：同标的、36 小时内、多数实词重叠。两个被测试逼出来的细节：仅差数字的标题是不同事件（"first-quarter revenue of 30 billion" vs "of 44 billion"），且短 token 过滤原本把 `Q1`、`up 5%` 里的数字也丢了。**配套**：门槛变得可达的同时也更容易被骗，所以一稿多发现在折叠为单一来源——检测按近似逐字而非精确字节，因为真实转载会小改标题。
      - [ ] 协调器状态持久化 + 限速执行器。
      - [ ] 补齐权威源适配器。
- [ ] **阶段 7 · 顾问调用层与补充调查闭环**
      接通顾问到真实模型调用，让补充调查请求有受理方，输出共识与分歧结构；把 ±3 封顶抽为共享常量。
- [ ] **阶段 8 · 专业图表与 UI 收口**
      捏合缩放、平移、十字光标、时间轴、横屏、复权切换；孤儿组件接线或删除；合并双主题体系并补暗色模式。
- [ ] **阶段 9 · 新加坡云端部署**
      云端 API 部署、设备配对、加密备份、缺失 runbook 补齐、TestFlight，实现 iOS 脱离 Mac。
- [ ] **阶段 10 · 校准与自适应学习闭环**
      审计存档 → 预测结果回填 → walk-forward/Brier 校准 → 顾问表现记忆。校准通过前禁止界面晋升 `CalibrationStatus`。随后再开全市场扫描、期权异动、社媒采集等新数据面。

## 四点五、第一轮客观评审的结果（2026-08-12）

对 `8a61cc9..HEAD` 的全部改动跑了 7 个独立评审代理 + 每条发现两名对抗性验证者。评审在我自己刚写的代码里找出了真实缺陷，全部已修并有测试固化：

| 缺陷 | 性质 |
|---|---|
| `except PointInTimeViolation` 是死代码，批次级未来数据仍被吞 | 我引入的守卫从未生效 |
| 非 ASCII `Authorization` 头令处理线程崩溃并打印含路径堆栈 | 认证前的安全缺陷 |
| 神龙指标把首个可测量 K 线报成"趋势转换" | 信号位置随取数窗口漂移 |
| `perfected` 在未检查时发布 `False` | 把"没检查"当成"检查过且不完美" |
| 量能确认测试两个分支产出完全相同 | 空转测试，已用变异验证修复后有效 |
| 无 K 线时发 `priceAdjustment: "unknown"` | 合法快照被 App 整份拒绝，空态不可达 |
| `received_at` 缺失时回退为最早值 | 恰好使截止校验失效 |
| 契约加必填字段却无版本信号 | 旧网关被报成"数据损坏"而非"版本过旧" |
| 四个屏幕在真实模式渲染演示分析 | 违反最重要的红线 |
| 顾问封顶三处口径不一（3 / 4 / 10） | App 把顾问权重夸大三倍以上 |
| README 白名单少一条、测试命令必然报错 | 文档与实现矛盾 |

评审共提出 40 条，其中 **29 条经对抗性验证被证伪**，11 条确认为真并全部修复。其中三条值得单独记：

- **中性 K 线终止计数被误报为"不可用"**：最后一根收盘价恰好等于四根前时，计算其实成功了、只是当前没有进行中的序列，却被标成不可用，导致真实存在的完美九转在界面上消失。可用性描述的是"能不能算"，零是一个答案。
- **相对成交量把当前 bar 计入自身基准**：50 倍放量只报 8.8 倍——用被放量抬高的均值去除放量本身。已改为"该 bar 之前二十根的简单均值"，与方法论文档声明一致，并有测试把两者绑在一起。
- **两处突变不被任何测试捕获**：`_is_perfected` 看跌分支改成恒真、TD 参考价从 close 改成 open，两套测试都全绿。已补上钉死规则的测试，并逐一验证突变确实会让它们变红。

教训写进流程：**测试必须先看到它变红**，并对关键断言做变异验证；**默认值不得填充恰好让校验通过的那个值**；**异常分类不要用字符串匹配**。

## 五、贯穿始终的红线

来自产品设计的十条不可妥协原则在每个阶段都适用，其中最容易被工程便利侵蚀的三条需要在每次评审时专门核对：

- 真实数据、代理数据、模型推断、演示数据必须显式区分；没有可靠数据时显示"不可用"，不得用装饰性假数据填充。
- 任何数据都按真实 `available_at` 截止；违规时序数据不得被静默修补或部分吞掉。
- 顾问只提供有上限的软因子，不能代替证据层与风控层。
