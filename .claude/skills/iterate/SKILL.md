# 一轮自动迭代

严格按顺序执行，一轮只做一项。

## 步骤

1. **取任务**：读 `docs/backlog.md`，取最上面的未勾选项。整个队列为空才去 roadmap 找新工作（并先把它写成 backlog 条目）。
2. **收窄范围**：只读该条目"改动范围"内的代码。需要探索时派 Explore 子代理，只带结论回来，不把大文件原文拉进上下文。
3. **测试先行**：先写一个会失败的测试来钉住完成标准，确认它以预期原因失败，再写实现。
4. **门禁**：`bash scripts/test_changed.sh` 全绿才算完成。修不绿就继续修；确认是环境性失败（见 CLAUDE.md 经验教训）才可说明后放行。
5. **提交**：小而完整的 commit，提交信息说清楚做了什么、为什么。
6. **记账**：更新 `docs/backlog.md`（勾掉完成项、写完成记录、把过程中发现的新问题按优先级插入队列）；踩到值得记住的坑，压缩成一行写进 CLAUDE.md 经验教训（遵守其上限与清理规则）。

## 纪律（省 token 的关键）

- 不顺手修队列外的问题——发现了就记入 backlog，本轮不动。
- 不做超出条目完成标准的"顺便重构"。
- 失败输出只看末尾摘要，不把整个测试日志反复读进上下文。
- 一轮结束就结束，不在同一会话里连续开第二轮（新会话上下文更干净、更省）。
