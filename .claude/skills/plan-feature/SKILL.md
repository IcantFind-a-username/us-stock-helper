# 拆解大任务为 backlog 条目

目的：杜绝马拉松会话。大任务先拆成小条目，再由 `/iterate` 逐轮消化。

## 步骤

1. 只读理解拆解所需的最少代码；需要探索时派 Explore 子代理，只带结论回来。
2. 把功能拆成若干条目，每条必须满足：
   - 单轮可完成（一个会话、一个中等大小的 commit）
   - 改动范围明确到目录
   - 完成标准可被测试验证
   - 按依赖顺序排列，前面的条目完成后后面的才可开工
3. 按优先级插入 `docs/backlog.md` 队列，遵守其条目格式。
4. 输出条目列表供用户过目，然后结束。

## 禁止

- 不写任何实现代码，不写测试，不"顺手先做第一条"。
- 拆不到单轮粒度的部分（如"重构整个模块"），继续往下拆；确实拆不动就先插入一个"调研并细化拆分"条目，把细化工作本身留给下一轮。
